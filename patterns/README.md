# Patterns

This directory contains mitigation and tightening patterns that respond to the
failure classes in `taxonomy/`.

Candidate patterns include:

- `reference governance shapes`
  A non-normative overview of recurring surfaces that make governance
  structurally real.
- `creation governance shape`
  Binds authority, scope, and baseline policy at object creation time.
- `data governance shape`
  Keeps governance metadata attached to data across storage, access, and
  movement.
- `execution governance shape`
  Treats runtime form, admission, dependencies, and attestation as governance
  surfaces.
- `interface governance shape`
  Exposes delegated scope, refusal semantics, and evidence hooks at API
  boundaries.
- `evidence governance shape`
  Records decision context and refusal in a replayable, verifier-usable form.
- `portability governance shape`
  Preserves governance posture across migration, export, exit, and rollback.
- `normative charter`
  Declares the value commitments that govern a framework before scoring begins.
- `omission register`
  Makes excluded values, stakeholders, and blind spots explicit rather than
  hidden.
- `counter-frame record`
  Forces alternative framings to be stated so one analytic frame does not
  become invisible doctrine.
- `deterministic measurement substrate`
  Keeps critical measurement and control logic outside narrative or stochastic
  reasoning loops.
- `coherence monitoring`
  Watches for relationship breakdown and structural instability before obvious
  threshold breach.
- `bounded AI role`
  Constrains AI to defined support functions rather than letting it become
  hidden authority.
- `policy as runtime`
  Requires claimed policy constraints to bind actual runtime behavior.
- `runtime evidence`
  Distinguishes replayable governance evidence from descriptive logging alone.
- `doctrine as coupling layer`
  Provides the strategic logic that keeps multiple policies aligned over time.
- `sovereignty requires verifier-friendly evidence`
  Makes sovereignty claims depend on exportable proof rather than branding or
  location rhetoric.
- `governance lifecycle validation`
  Connects pre-deployment design validation to runtime envelope monitoring and
  intervention.
- `delegated agent identity`
  Treats agent identity as delegated execution identity, not standalone legal
  personhood.
